다음 최초 채점 결과에서 가장 보완이 필요한 문항을 기준으로 꼬리질문 1개와 채점용 모범답안을 생성하세요.

## 입력

### 최저점 문항 번호
{{weakestQuestionId}}

### 원래 질문
{{questionText}}

### 사용자 답변
{{userAnswer}}

### 채점 feedback
{{feedback}}

## 꼬리질문 생성 원칙

- 원래 질문과 사용자 답변, feedback을 근거로 답변에서 부족했던 부분을 정확히 겨냥하세요.
- 이미 충분히 답한 내용을 반복해서 묻지 말고, 원래 질문이 요구한 범위 안에서 빠진 핵심
  개념 또는 판단 근거 하나만 확인하세요.
- 원래 질문에 없던 새로운 고난도 주제, 구현 패턴, 정량 지표, 복수의 트레이드오프나
  극단적 예외 상황을 추가로 요구하지 마세요.
- 최초 질문 생성과 같은 면접관 톤을 유지하되, 질문은 하나만 생성하세요.
- few-shot 예시의 문장을 그대로 베끼지 말고, 구조와 깊이만 참고하세요.
- expectedAnswer는 완전한 정답 목록이 아니라 평가 참고 기준입니다. 기존 답변에서 누락된
  핵심 개념과 그 이유만 간결하게 포함하고, 새 평가 요구사항을 추가하지 마세요.
- 개인정보를 새로 만들거나 추정하지 마세요.

## Few-shot 예시

### 예시 1
원래 질문: "캐시를 도입하면서 발생할 수 있는 정합성 문제는 어떻게 처리했나요?"
사용자 답변: "캐시는 DB 부하를 줄여주기 때문에 사용했습니다."
feedback: "캐시 도입 이유만 언급했고, DB와 캐시 간 데이터 정합성 문제와 처리 전략이 빠져 있습니다."
출력 꼬리질문: "DB와 캐시의 값이 서로 달라질 수 있는 상황을 하나 들고, 그 상황에서 어떤 무효화 또는 갱신 전략을 적용할지 설명해 주세요."
출력 모범답안: "DB 변경 후 캐시를 무효화하거나 갱신해 오래된 값이 남는 시간을 줄인다는 핵심 원리와 선택 이유를 설명한다."

### 예시 2
원래 질문: "인덱스를 추가할 때 어떤 기준으로 컬럼 순서를 정하나요?"
사용자 답변: "조회가 빠르게 되도록 인덱스를 겁니다."
feedback: "조회 성능 개선이라는 목적은 맞지만, WHERE 조건의 사용 순서를 컬럼 순서에 반영하는 판단 근거가 부족합니다."
출력 꼬리질문: "복합 인덱스의 컬럼 순서를 WHERE 조건의 사용 순서에 맞춰 정하는 이유를 설명해 주세요."
출력 모범답안: "실제 WHERE 조건의 사용 순서를 기준으로 복합 인덱스 컬럼 순서를 정하는 이유를 설명한다."

## 출력 형식

아래 JSON 객체만 반환하세요. 마크다운 코드블록, 설명 문장, 주석은 절대 포함하지 마세요.

{
  "followUpQuestion": "꼬리질문 본문",
  "expectedAnswer": "채점에 사용할 모범답안"
}

## 출력 검증 규칙

- followUpQuestion과 expectedAnswer는 빈 문자열이면 안 됩니다.
- followUpQuestion은 하나의 질문만 포함해야 합니다.
- expectedAnswer는 API 응답 화면에 노출되지 않고 최종 채점 내부에서만 쓰인다는 전제로 작성하세요.
