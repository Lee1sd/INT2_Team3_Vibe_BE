# 이 파일은 src/main/resources/prompts/**의 스냅샷입니다.
# 실제 코드가 SSOT이며, 이 문서는 히스토리 기록용입니다

다음 이력서 내용과 선택 키워드를 바탕으로 기술 면접 질문 3개와 각 질문의 모범답안을 생성하세요.

## 입력

### 선택 키워드
{{keyword}}

### 이력서 텍스트
{{resumeText}}

## 질문 생성 원칙

- 질문은 반드시 선택 키워드와 이력서에 드러난 경험, 기술, 프로젝트 맥락을 함께 반영하세요.
- 이력서에 선택 키워드와 직접 관련된 경험이 없으면, 이력서 내용을 억지로 끌어쓰지 말고 일반적인 CS 지식 관점에서 질문을 만드세요.
- 이 질문은 매번 새로 생성해야 하며, 미리 정해진 질문 목록에서 고르거나 이전에 생성한 질문을 재사용해서는 안 됩니다.
- few-shot 예시의 문장을 그대로 베끼지 말고, 스타일만 참고해서 이번 이력서/키워드에 맞는 새로운 질문을 만드세요.
- 질문은 turn 1, 2, 3 순서로 난이도가 조금씩 깊어지게 구성하세요.
- 각 모범답안은 채점 기준으로 재사용할 수 있도록 핵심 개념, 판단 근거, 실무 적용 포인트를 포함하세요.
- 질문과 모범답안에는 사용자에게 노출해도 되는 기술 정보만 사용하고, 개인정보를 새로 만들거나 추정하지 마세요.

## Few-shot 예시

### 예시 1
입력 키워드: DB
이력서 단서: "Spring Boot API에서 게시글 목록 조회가 느려져 실행 계획을 확인하고 인덱스를 조정했다."
출력 질문: "게시글 목록 조회가 느려졌을 때 실행 계획에서 어떤 지표를 보고 인덱스 개선 여부를 판단하셨나요?"
출력 모범답안: "실행 계획에서 type, key, rows, filtered, Extra를 확인하고 풀스캔 여부와 정렬/임시 테이블 사용 여부를 본다. WHERE, JOIN, ORDER BY에 자주 쓰이는 컬럼의 선택도와 카디널리티를 고려해 복합 인덱스 순서를 정하고, 쓰기 비용과 저장 공간 증가도 함께 판단한다."

### 예시 2
입력 키워드: 클라우드
이력서 단서: "Docker와 GitHub Actions로 백엔드 배포를 자동화했다."
출력 질문: "Docker 기반 배포 파이프라인에서 새 버전 배포 중 장애가 발생하면 어떤 기준으로 롤백을 판단하시겠어요?"
출력 모범답안: "헬스체크 실패, 오류율 증가, 응답 지연, 주요 API 스모크 테스트 실패를 롤백 기준으로 둔다. 이미지 태그와 배포 이력을 남겨 이전 안정 버전으로 되돌릴 수 있게 하고, 환경 변수와 DB 마이그레이션처럼 롤백이 어려운 변경은 배포 전 별도 검증과 순차 배포 전략을 적용한다."

## 출력 형식

아래 JSON 객체만 반환하세요. 마크다운 코드블록, 설명 문장, 주석은 절대 포함하지 마세요.

{
  "questions": [
    {
      "turn": 1,
      "questionText": "질문 본문",
      "expectedAnswer": "채점에 사용할 모범답안"
    },
    {
      "turn": 2,
      "questionText": "질문 본문",
      "expectedAnswer": "채점에 사용할 모범답안"
    },
    {
      "turn": 3,
      "questionText": "질문 본문",
      "expectedAnswer": "채점에 사용할 모범답안"
    }
  ]
}

## 출력 검증 규칙

- questions 배열 크기는 정확히 3이어야 합니다.
- turn은 정수 1, 2, 3을 각각 한 번씩만 사용해야 합니다.
- questionText와 expectedAnswer는 빈 문자열이면 안 됩니다.
- expectedAnswer는 API 응답 화면에 노출되지 않고 채점 로직 내부에서만 쓰인다는 전제로 작성하세요.
