## ② 면접 엔진 + LLM (김한비)

> **작업 순서(v5.2 신규 명시)**: 인터페이스 추상화(1순위) → 응답 방어(2순위) →
> 페르소나 설계/프롬프트/질문 생성. Mock 구현체만 먼저 나오면 ③ 담당(최용성)이
> "이런 형식의 JSON이 온다"를 가정하고 채점 루틴(JSON→점수 변환)을 바로 시작할
> 수 있고, JSON 스키마(필드명·타입: `evaluations`, `totalScore`, `weakestQuestionId`,
> `passed` 등)가 확정되어야 최용성이 그 형식에 맞춰 점수 변환 로직을 정확히 짤 수
> 있기 때문입니다. 이 순서 때문에 페르소나 설계·프롬프트·질문 생성의 중요도가
> 상→중으로 낮아졌습니다(중요하지 않다는 뜻이 아니라, 순서상 나중이라는 뜻).

| 작업 | 세부 항목 | 중요도 | 비고 |
| --- | --- | --- | --- |
| 인터페이스 추상화 | LLM 클라이언트 인터페이스, Mock 구현체 | 상 | **1순위** — Mock만 있어도 최용성이 채점 루틴 개발을 바로 시작 가능 |
| 응답 방어 | JSON 스키마 검증, 파싱 실패 재시도/폴백 | 상 | **2순위** — 최용성이 받을 JSON 필드명/타입이 확정되어야 점수 변환 로직을 정확히 짤 수 있음 |
| 페르소나 설계 | 대리/과장 2종 스타일 엔진(말투/피드백 성향) | 중 | (v5.1: 상 → v5.2: 중, 순서상 후순위로 조정) |
| 프롬프트 | 템플릿 설계, 이력서 키워드 주입 로직 | 중 | (v5.1: 상 → v5.2: 중) |
| 질문 생성 | 이력서+키워드 기반 프롬프트 조립 로직 | 중 | (v5.1: 상 → v5.2: 중) |
