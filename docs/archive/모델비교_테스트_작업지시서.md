## 배경

지금까지는 "질문 생성 관련성"만 1회씩 비교했는데, 우리 서비스에서 LLM이 하는 일은 4가지입니다. 모델 선택을 위해선 4가지 다 봐야 합니다.

| # | LLM 작업 | 확인 상태 |
|---|---|---|
| 1 | 질문 생성 (4개) | ✅ 1회 확인함 (이력서 1개) |
| 2 | 최초 채점 (4문항×5항목=20개 숫자) | ❌ 미확인 |
| 3 | 꼬리질문 생성 (최저점 문항 타겟) | ❌ 미확인 |
| 4 | 최종 채점 + 종합피드백 | ❌ 미확인 |

**질문을 먼저 생성해봐야 그 질문에 맞는 답변을 쓸 수 있으므로**, 아래는 2단계로 나눕니다.

---

## Phase 1 — 질문 생성 비교 (이력서 10개 전체)

이미 준비된 이력서 10개(팀원 실이력서 4개 + AI 생성 6개) 전부에 대해:

1. **키워드 매핑**: 각 이력서의 강점 도메인에 맞춰 DB 또는 보안 키워드 지정
   - AI생성 이력서 매핑 예시: 1번(커머스)→DB, 2번(채팅)→보안, 3번(파이프라인)→DB, 4번(교육)→보안, 5번(여행/프론트)→DB 또는 보안 중 하나로 (약한 신호 테스트), 6번(비전공)→DB 또는 보안 (완전 무관 폴백 테스트)
2. Haiku/Sonnet 각각으로 질문 생성 — 레벨당 4개씩(Lv1 4개 + Lv2 4개 = 모델당 총 8개), Lv1/Lv2 둘 다 생성 (난이도 격차 확인 목적)
3. **확인 사항**:
   - 이력서 관련성·구체성 (기존과 동일)
   - **레벨(Lv1/Lv2) 간 난이도 격차가 이력서 관련성 수준(풍부/보통/희박)과 무관하게 일관되게 유지되는가** — 신규 확인 축
   - JSON 파싱 실패 여부 (코드펜스 등 스키마 이탈)

---

## Phase 2 — 채점/꼬리질문 비교 (이력서 3개 선정, 답변은 질문 생성 후 작성)

**전체 10개가 아니라 3개만 선정** — 관련성 수준별로 하나씩 (작업량 관리):
- 이력서 1 (DB, 관련성 풍부)
- 이력서 4 (보안, 관련성 보통)
- 이력서 6 (완전 무관, 엣지케이스)

각 이력서마다:

1. Phase 1에서 생성된 질문 4개(모델별로 다를 수 있음 — 모델별로 각각 진행)를 확인
2. **그 질문에 맞춰 답변 4개 작성**: 3개는 준수한 답변, **1개는 의도적으로 약한 답변**(예: 핵심 개념 누락, 트레이드오프 언급 없음) — 이게 꼬리질문이 정확히 이 문항을 타겟하는지 확인하는 장치
   - 답변 작성은 워커가 직접 쓰거나, 필요하면 PM(Claude)에게 "이 질문에 대한 약한 답변 초안 써줘" 요청 가능 — 질문이 나온 뒤에 그때그때 요청
3. 최초 채점 실행 → **확인**: 약한 답변에 낮은 점수가 정확히 매겨지는가, 두 모델 간 점수 편차가 크지 않은가
4. 꼬리질문 생성 → **확인**: 의도적으로 약하게 쓴 문항을 정확히 타겟하는가
5. 꼬리질문에 답변(적당한 수준) 작성 → 최종 채점 → **확인**: 최종 점수 타당성

> ⚠️ **"종합피드백 품질" 확인은 FR-14(섹션형 리포트: 총평/강점/성장포인트/Next Step) 구현 완료 후 진행**할 것. FR-14 이전엔 종합피드백이 옛날 방식(2~4문장 단문)이라, 지금 비교하면 실제 채택될 리포트 형식과 다른 걸 테스트하게 됨. FR-14 담당자 구현 완료 확인 후 이 항목만 별도로 재실행.

## 공통 확인 사항 (전 과정에서 기록)

- JSON 파싱 실패/재시도 횟수 (모델별 누적)
- 응답 시간(latency) 체감 — 폴링 방식이라 3~10초 기준 커버되는지
- **API 사용량은 호출 단계별로 구분해서 기록** (①질문생성 / ②최초채점 / ③꼬리질문생성 / ④최종채점, 각각 토큰·비용 별도 기재) — "어느 단계만 Sonnet으로 바꿨을 때 비용이 얼마나 늘어나는지" 계산 근거로 필요 (`모델_선정_기준.md` 2차 판단 절차 3번 참고)

- Phase 2(약한답변/채점/꼬리질문 확인)는 Phase 1 질문 결과 나온 뒤, 답변 작성 후 진행
