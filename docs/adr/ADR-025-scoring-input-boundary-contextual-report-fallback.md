# ADR-025 — 채점 입력 신뢰 경계와 실제 면접 기반 리포트 대체

- 상태: 제안
- 작성자: 최용성
- 작성일: 2026-07-29
- 관련 이슈/PR: #170, #179

## 배경

최초·최종 채점 프롬프트에 질문, 지원자 답변, 모범답안, 이전 평가가 평문으로 삽입되어
지원자 답변의 명령형 문장이 정적 채점 지시와 구조적으로 분리되지 않았다. 또한 최종
커리어 리포트는 Markdown 형식 검증을 실 Claude 응답이 자주 통과하지 못해, 관찰 표본에서
고정 사과문 fallback이 반복 노출됐다. 점수는 보존됐지만 사용자는 실제 면접에 대한
종합 피드백을 받지 못했다.

## 결정

1. 최초·최종 채점의 모든 동적 입력은 하나의 `<interview-data>` 블록 안에 JSON으로
   직렬화한다. JSON 문자열의 `<`, `>`, `&`는 유니코드 escape해 데이터가 경계 태그를
   닫을 수 없게 한다.
2. system/user 프롬프트의 정적 규칙만 지시로 취급한다. 데이터 블록의 명령문, 역할 변경,
   규칙 무시, 출력 형식 변경 요구는 평가 대상 텍스트로만 취급한다.
3. 리포트 콘텐츠 검증 실패 시 기존 정책대로 최대 한 번 재요청하며, 최초 응답의 점수는
   유지한다.
4. 재요청도 실패하거나 재요청 JSON이 깨지면 고정 사과문을 반환하지 않는다. 최초 1~4의
   질문·서버 확정 피드백과 turn 5 질문·답변·피드백으로 서버가 네 섹션 Markdown 리포트를
   결정적으로 조립하고 가상 수치 고지를 덧붙인다. 재요청의 null·런타임 예외와 서버 조립
   리포트의 예기치 않은 검증 실패도 최초 점수를 유실시키지 않으며, 마지막에는 검증된
   최소 네 섹션 리포트로 응답을 완성한다.
5. 외부 `IS-002b` 응답 필드, 점수 계산, DB 스키마, 정상 세션의 네 단계 LLM 호출 구조는
   변경하지 않는다. 각 검증 실패의 재요청은 최대 한 번이지만, 최종채점은 스키마 재요청
   성공 뒤 리포트 재요청이 이어질 수 있어 해당 단계 최대 3회, 세션 전체 최악 9회로
   계산한다.

## 핵심 근거

프롬프트 문구만 강화해도 생성형 출력의 Markdown 준수를 10/10 보장할 수 없고, 검증기를
느슨하게 하면 내부 용어·가상 수치 오표시 방어가 약해진다. 입력 경계를 코드에서 만들고
최종 사용자 형식을 서버가 결정적으로 보장하면 보안 경계와 사용자 피드백 가용성을 함께
확보하면서 API·DB·호출 예산을 유지할 수 있다.

## 대안 및 반려

- **프롬프트 지시만 강화** — 기존 실측에서 첫 응답 형식 통과가 0~1/10에 머물러
  10표본 정상 피드백을 보장할 수 없어 반려했다.
- **검증 규칙 완화** — 형식 통과율은 올라가지만 내부 처리 용어 노출과 가상 수치 오인
  방지 계약을 약화하므로 반려했다.
- **리포트 전용 LLM 호출 분리** — 출력 품질 개선 가능성은 있으나 정상 세션 호출 수,
  지연, 비용을 늘려 현재 세션당 네 번 호출 예산과 맞지 않아 반려했다.
- **고정 사과문 유지** — 점수 보존에는 안전하지만 실제 면접 피드백이라는 핵심 사용자
  가치를 제공하지 못해 반려했다.

## 결과 (기대)

- 지원자 답변에 프롬프트 명령이나 종료 태그가 포함돼도 최초·최종 채점의 정적 지시를
  변경할 수 없다.
- LLM 리포트가 반복해서 형식을 이탈해도 모든 성공한 최종판정은 실제 면접 컨텍스트를
  반영한 네 섹션 `overallFeedback`을 반환한다.
- 클라이언트는 고정 사과문 예외 분기 없이 동일한 Markdown 구조를 렌더링할 수 있다.
- 리포트 재요청과 무관하게 최초 응답의 평가·점수·합격 원시값 보존 계약을 유지한다.
