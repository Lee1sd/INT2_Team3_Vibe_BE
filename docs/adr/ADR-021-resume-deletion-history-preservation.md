# ADR-021 — 개별 이력서 삭제 시 면접 히스토리 보존

- 상태: 제안
- 작성자: 이건희
- 작성일: 2026-07-21
- 관련 API: RS-004

## 배경

`interview_sessions.resume_id`는 `resumes.id`를 참조하며 ADR-016/V11에 의해 `ON DELETE
CASCADE`가 설정되어 있다. 따라서 이력서 행을 그대로 삭제하면 연결된 면접 세션뿐 아니라
메시지, 질문, 채점 결과도 연쇄 삭제된다. 이는 사용자가 개별 파일을 정리하는 동작 때문에
이미 완료한 면접 히스토리를 잃게 만든다.

한편 회원 탈퇴는 개인정보 정책상 전체 즉시 삭제가 필요하므로 ADR-016의 캐스케이드는
유지해야 한다. TTL 만료 시에는 `ParseStatus.EXPIRED`로 전이하고 `extractedText`만 파기하는
배치가 이미 구현되어 있다. TTL 역시 면접 히스토리 FK를 보존하기 위해 Resume 행을 유지하지만,
사용자의 직접 삭제는 원본 위치 키와 파일 해시까지 즉시 파기한다는 점에서 처리 범위가 다르다.

## 결정

개별 삭제 API는 소유 이력서의 `deleted_at`을 기록하는 소프트 삭제를 수행한다. 삭제된 이력서는
사용자 상태 조회·목록·업로드 개수 계산·FAILED 슬롯 재사용 대상에서 제외한다. 행과 FK는
유지하므로 면접 세션의 히스토리는 계속 기존 이력서를 참조할 수 있다. 타인 소유, 존재하지 않는
ID, 이미 삭제된 ID는 모두 404로 처리한다.

삭제 후 활성 이력서가 0개인 상태는 허용하되, 기존 FR-01의 "이력서 필수"는 면접 세션 생성
조건으로 적용한다. 사용자는 새 이력서를 업로드하기 전까지 새 면접을 시작할 수 없다.

회원 탈퇴 경로는 기존 `ON DELETE CASCADE`를 그대로 사용해 전체 데이터를 즉시 삭제한다.

원본 파일 삭제는 DB 커밋 이후 실패할 수 있으므로 소프트 삭제 UPDATE와 같은 트랜잭션에서
V17의 `resume_file_cleanup_tasks`에 작업을 기록하고, 10분 주기의 배치가 로컬 파일 삭제를
재시도한다. 따라서 삭제 표시와 작업 기록은 함께 커밋되거나 함께 롤백된다. 작업에는 `resumeId`,
`s3Key`, 생성 시각, 상태, 시도 횟수와 최근 시도 시각을 저장한다. 파일 삭제에 성공한 경우에만
작업을 삭제하며 실패한 작업은 다음 주기에 다시 처리한다. S3 연동 후에도 저장소 삭제 구현만
교체하고 같은 작업 구조를 재사용한다.

작업 테이블은 Resume FK를 두지 않는다. 회원 탈퇴 CASCADE로 Resume 행이 먼저 사라져도 아직
남아 있는 원본 파일을 계속 정리할 수 있어야 하기 때문이다. `s3Key`는 파일 정리 성공 시 즉시
삭제하며, 실패 작업은 유실 방지를 위해 성공할 때까지 보관한다. 운영상 30일 이내 해결을 목표로
30일 이상 실패한 작업은 수동 점검 대상으로 취급하되, 파일 삭제 확인 전에는 자동 만료시키지 않는다.

## 핵심 근거

- 기존 면접 세션의 `resume_id`는 NOT NULL이고 엔티티 연관도 필수라서, FK만 `SET NULL`로
  바꾸면 스키마와 도메인 불변식을 함께 변경해야 한다.
- 소프트 삭제는 interview 도메인의 엔티티나 API 계약을 변경하지 않고 삭제 버튼 동작과
  히스토리 보존을 모두 만족한다.
- 소유권 조회를 참조 여부 확인보다 먼저 수행해 타인의 이력서 사용 여부가 노출되지 않는다.

## 대안 및 반려

- `ON DELETE CASCADE` 그대로 물리 삭제: 면접 히스토리까지 사라지므로 반려한다.
- 참조 중인 이력서 삭제 거부: 히스토리는 보존하지만 사용자가 삭제 버튼으로 파일을 정리할 수
  없으므로 반려한다.
- `resume_id`를 nullable로 바꾸고 `ON DELETE SET NULL`: 파일 삭제는 가능하지만 면접 생성·조회
  코드와 엔티티 불변식 변경이 필요해 이번 범위를 크게 넘으므로 반려한다.
- 이력서 스냅샷을 면접 세션에 별도 저장: 가장 독립적인 히스토리를 만들 수 있으나 스키마와
  개인정보 보존 정책을 새로 설계해야 하므로 후속 개선안으로 남긴다.

## 결과

- 참조 여부나 남은 개수와 관계없이 본인 이력서/포트폴리오를 사용자 화면에서 삭제할 수 있다.
- 삭제된 행은 유지되어 기존 면접 히스토리가 계속 참조할 수 있다.
- 회원 탈퇴의 전체 즉시 삭제 동작에는 변화가 없다.
