# ADR-005 — 이력서 컨텍스트 주입 방식: 직접 주입 (Vector DB/RAG 탈락)

- 상태: 승인 (기획서 v5.1, 16장)
- 근거 문서: 기획서 16장(ADR)

## 배경

질문 생성·채점 시 이력서/포트폴리오 추출 텍스트를 LLM에 어떻게 공급할지 정해야 한다.
후보는 (a) 프롬프트에 전체 텍스트를 직접 주입, (b) Vector DB에 임베딩해 RAG로
관련 조각만 검색해 주입.

## 결정

**직접 주입**으로 확정한다 (Vector DB/RAG 탈락). 추출된 이력서 텍스트(PII 마스킹
완료본) 전체를 프롬프트에 그대로 포함한다.

## 핵심 근거

- 이력서는 A4 1~2장 분량으로 충분히 작아, 전체를 프롬프트에 넣어도 컨텍스트 윈도우
  제한에 걸리지 않는다.
- Vector DB 구축(임베딩 파이프라인, 유사도 검색 인프라)에 드는 공수 대비 실익이
  이 프로젝트 규모에서는 없다.

## 대안 및 반려

- **Vector DB + RAG** — 반려. 이력서 분량이 작아 RAG가 주는 이점(대용량 문서에서
  관련 부분만 검색)이 발생하지 않고, 3주 일정에 임베딩 인프라 구축 비용을 들일
  이유가 없다.

## 결과 (기대)

- `domain.resume`이 반환하는 `extractedText`(마스킹됨)를 `domain.interview`/
  `domain.message`가 그대로 프롬프트에 조립한다. 별도 검색·임베딩 단계가 없다.
- 이력서 분량이 예상보다 커지는 경우(예: 다수 프로젝트 상세 포함 긴 포트폴리오)
  프롬프트 토큰 비용이 커질 수 있다는 점은 리스크로 남아 있다 — 필요 시 요약 전처리를
  추가 검토할 수 있으나 MVP 범위에는 없다.
