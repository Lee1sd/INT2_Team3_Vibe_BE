# ADR-013 — 질문 생성 시 질문 3개 + 모범답안을 단일 LLM 호출로 함께 생성

- 상태: 제안
- 작성자: 김한비
- 작성일: 2026-07-14
- 관련 이슈/PR: #38, [ADR-009](ADR-009-judgment-evaluation-port.md)

## 배경

이슈 #38(질문 생성 프롬프트: 이력서+키워드 기반 3문항+모범답안 일괄생성)을 구현하려면
"질문 생성"과 "각 질문의 모범답안(`expectedAnswer`) 생성"을 하나의 LLM 호출로 묶을지,
두 단계로 나눠 호출할지 정해야 한다.

세션당 AI 호출 횟수는 이슈 #50 재검증 결과 기준으로 4회로 확정한다. ①질문생성,
②최초채점, ③꼬리질문생성, ④최종채점으로 계산한다. 최초채점과 꼬리질문생성은
③(judgment)과 ②(interview) 도메인 분리로 통합 불가하므로 별도 호출로 유지한다.
`docs/operations/llm-cost-policy.md`도 이 4회 기준을 따른다. 질문 생성과 모범답안 생성을
분리 호출하면 질문 생성 영역에서 호출 수가 불필요하게 늘어나므로 금지한다.

## 결정

질문 생성 API(IS-001)는 최초 질문 3개와 각 질문의 모범답안(`expectedAnswer`)을
**한 번의 LLM 호출**로 함께 생성한다. 질문 생성과 모범답안 생성을 별도 호출로 분리하지 않는다.
꼬리질문은 최초 채점 이후 `weakestQuestionId`가 정해져야 생성할 수 있으므로 이 IS-001
호출에 포함하지 않고, 두 번째 LLM 호출인 꼬리질문 재채점 호출 안에서 생성과 재채점을
함께 처리한다.
`LlmClient`/`MockLlmClient` 양쪽 모두 이 단일 호출 계약을 따르며, 응답 스키마는 질문
3개와 모범답안 3개가 1:1로 대응해야 한다(개수 불일치는 스키마 검증 실패로 처리).

## 핵심 근거

- 세션당 AI 호출 횟수 기준(4회) 안에서 질문 생성 영역의 추가 호출을 막는 방법이다. 최초
  질문과 모범답안을 분리 호출하면 질문 생성 단계의 호출 수가 불필요하게 늘어난다.
- 질문과 모범답안을 같은 컨텍스트(이력서, 키워드, 페르소나)에서 한 번에 생성하면 질문과
  답안 사이의 논리적 일관성(질문이 요구하는 깊이와 모범답안의 깊이가 어긋나지 않음)을
  프롬프트 설계만으로 보장하기 쉽다.

## 대안 및 반려

- **질문 생성 후 모범답안 별도 호출** — 프롬프트를 단순하게 유지할 수 있지만 최초 질문 생성
  단계의 호출 예산(1회)을 초과하므로 반려.

## 결과 (기대)

- IS-001 응답 계약(`questions[].question`)은 그대로 유지되고, `expectedAnswer`는 응답에
  노출하지 않은 채 서버 내부에서 `questions` 테이블(`message_id` FK, `expected_answer`
  컬럼)에 저장된다.
- `questions` 테이블에 저장된 모범답안은 judgment 도메인(③, 최용성 담당)의 채점 입력
  기준값으로 그대로 소비된다 — [ADR-009](ADR-009-judgment-evaluation-port.md)가 정의한
  "LLM이 평가 원시값을 반환하는 시점까지가 ②의 책임"이라는 경계와 일치한다.
- 질문 생성 LLM 응답의 JSON 스키마 검증(질문 3개·모범답안 3개 개수·필드 존재 여부)이
  하나의 검증 경로로 통합되어 `LlmResponseValidator` 쪽 분기가 늘어나지 않는다.
