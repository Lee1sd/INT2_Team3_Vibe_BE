# llm-cost-policy.md — LLM 비용/모드 운영 정책

> 근거: `[기획서] 커리어 던전 v5.1.pdf` 12장(리스크: 무제한 재도전 비용 방어), 18장(테스트
> 전략: Mock 활용 전략, API 키 관리). 관련 요구사항: NFR-11, `CM-001`. 이 문서는
> `docs/ai/SHARED.md` §3 역방향 추적 ⑥(비용/시간 가드)의 판단 기준입니다.

## 1. 기본 원칙: Mock이 기본값

- **개발 중에는 항상 Mock LLM 모드(고정 JSON 반환)를 사용한다.** 실제 벤더 API를
  호출하는 코드 경로는 기본적으로 비활성화되어 있어야 한다.
- **실 API 호출은 다음 두 상황에만 한정한다**: (1) 통합 테스트, (2) 데모 리허설/데모
  당일. 그 외 상황(로컬 개발, 단위 테스트, 리뷰)에서는 Mock을 쓴다.
- Mock 구현체는 `LlmClient` 인터페이스의 한 구현체일 뿐이며, 어떤 구현체를 쓸지는
  설정(프로필/환경변수)으로 전환한다. 도메인 코드가 "지금 Mock인지 실제인지"를 몰라도
  동작해야 한다(NFR-09 벤더 추상화와 동일한 원칙).

## 2. 예산 상한 (1차 방어선)

- 공용 API 키 **1개**를 통합 관리한다. 개인 키를 임의로 추가하지 않는다.
- **월 예산 상한(hard limit)**을 설정한다. 이것이 "무제한 재도전 시 비용 증가" 리스크에
  대한 1차 방어선이다(기획서 12장).
- 실사용 모니터링 후 필요하면 재도전 횟수 제한(스트레치골, `FEAT-21` "AI 재도전 하루
  5개 제한")을 2차 방어선으로 추가 검토한다. **MVP 범위에는 재도전 횟수 제한이 없다** —
  예산 상한만으로 1차 방어한다는 점을 착각하지 않는다.
- API 키 관리: 환경변수로만 관리한다. 하드코딩 금지, GitHub 커밋 금지
  (`.gitignore`에 `.env`류가 포함되어 있는지 주기적으로 확인).

## 3. 세부 모델 선택 (확정: Haiku 4.5)

- 벤더는 Claude로 확정(`docs/adr/ADR-003-llm-vendor-selection.md`). 세부 모델은
  **Haiku 4.5로 확정**한다 — Mock 답변 기준 Haiku/Sonnet 비교 테스트에서 채점 방향·
  feedback 품질 동등, 점수 편차는 기획서 §12 감수 범위 내, 비용이 3주 예산에 더
  적합해 채택 (`FEAT-13`, `docs/adr/ADR-007-llm-model-selection-haiku45.md`).
- 확정 전까지 모델명을 코드에 하드코딩하지 않는다 — 설정값으로 분리한다.
- 모델 선택 기준(확정 후 이 절을 갱신할 것): 채점 일관성(NFR-08), 응답 속도(폴링
  타임아웃과 연동, NFR-04), 비용.

## 4. 호출 횟수 가드

- 질문 생성(FR-03)은 세션당 1회 호출로 질문 3개 + 모범답변 3개를 함께 생성한다(호출
  횟수를 늘리지 않기 위한 설계 — "API 호출 횟수 유지"가 기획서 원문 근거).
- 채점(FR-04)은 1차 배치채점 1회 + 꼬리질문 재채점 1회, 세션당 최대 2회 채점 호출로
  고정한다.
- JSON 스키마 검증 실패 시 **최대 2회 재요청**까지만 허용한다(NFR-05). 재요청 횟수를
  이 상한보다 늘리는 변경은 반드시 이 문서를 먼저 갱신한다 — 재요청은 곧 추가 비용이다.

## 5. 역방향 추적 ⑥ 체크리스트에 대응하는 질문

새 코드가 LLM을 호출한다면 아래를 확인합니다.

- [ ] 기본 프로필에서 Mock 구현체가 선택되는가?
- [ ] 이 호출이 세션당 호출 횟수 상한(질문 생성 1회, 채점 최대 2회)을 넘지 않는가?
- [ ] JSON 파싱 실패 시 재요청이 최대 2회로 제한되어 있는가?
- [ ] 모델명이 하드코딩되지 않고 설정값으로 분리되어 있는가?
